SLIDE 8
DRY Principle: Don't Repeat Yourself
1. Redundant Implementation
Repeated code blocks lead to maintenance nightmares and increased bug potential. Imagine updating identical logic in multiple places.
2. Functional Abstraction
Encapsulate repetitive logic within a single, reusable function. This promotes modularity and simplifies future modifications.
3. Pattern Generalization
Abstract common behaviors into higher-order functions or classes. This avoids repetition across diverse modules and contexts.

SLIDE 9
Convoluted Approach: Over-engineering
Minimalist Approach: KISS in Practice
Consider a function to calculate the sum of two numbers. An over-engineered solution might involve creating a class, multiple methods, and extensive error handling for non-numeric inputs, even when requirements dictate valid inputs. This introduces unnecessary complexity and a higher cognitive load for maintainers. It obscures the core functionality.
The KISS principle advocates for the simplest viable solution. For the sum function, a direct arithmetic operation is sufficient. This approach minimizes code, reduces potential bugs, and enhances readability. Simple designs are easier to understand, test, and maintain, aligning with agile development principles.

SLIDE 10
YAGNI vs. Premature Optimization
YAGNI (You Ain't Gonna Need It)
YAGNI advocates against adding functionality until it's absolutely necessary. It prevents scope creep and unnecessary complexity, saving development time and resources. This principle focuses on current requirements, deferring speculative future features. Over-engineering is a primary risk of ignoring YAGNI.
Premature Optimization
This involves optimizing code for performance before identifying actual bottlenecks. It often wastes effort on non-critical sections, introducing complexity without significant benefit. 
Donald Knuth
 famously stated, "Premature optimization is the root of all evil." Focus on clear, correct code first, then optimize empirically.

SLIDE 13
Poor Naming Conventions
Effective Naming Conventions
Ambiguous names hinder readability and maintainability. Avoid single-letter variables (e.g., `x`, `y`) unless for simple loop counters. Functions like `doStuff()` offer no clear intent, forcing developers to guess their purpose. Such practices increase cognitive load and introduce errors.
Descriptive names are crucial for code clarity. Use meaningful variable names (e.g., `customer_id`, `total_amount`). Functions should clearly state their action and object (e.g., `calculate_average_score()`, `process_user_data()`). This enhances understanding and reduces debugging time.

SLIDE 14
Identifying Code Smells
Long Method
Methods exceeding typical length often indicate multiple responsibilities. Refactor by extracting smaller, focused functions to improve readability and maintainability.
Duplicate Code
Identical code blocks appearing in various places violate the DRY principle. Consolidate these into reusable functions or classes to prevent inconsistencies.
Large Class
Classes with excessive responsibilities become difficult to manage. Decompose them into smaller, cohesive classes, each with a single, clear purpose.
