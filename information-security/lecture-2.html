Slide 3 of 7 · Open in PDF
Easy explanation

The avalanche effect describes a large output change in response to a small input change. A common experiment flips a single input bit while keeping other settings fixed.

Example: Change one bit of a message and compare the two output bit strings.

Key terms to remember
  • Avalanche effect: A phenomenon where a small change in input leads to a significant change in output; flipping a single bit can cause this change.
Slide 4 of 7 · Open in PDF
Easy explanation

The slide compares ciphertext for ISUECCSICT and iSUECCSICT. It does not specify the key, mode, IV or padding, so its claimed Blowfish outputs cannot be independently reproduced from the information given.

Example: ASCII I is 0x49 and i is 0x69: their XOR is 0x20, a one-bit change.

Key terms to remember
  • Ciphertext: The encrypted result generated by the Blowfish algorithm for an input.
  • Blowfish: A symmetric-key block cipher with a 64-bit block size; the lesson uses it as an example for comparison.
  • Controlled comparison: Compare outputs from the same algorithm and key with settings held constant while changing the intended input bit.
  • Reproducibility settings: To reproduce encrypted output, specify the key, mode, IV or nonce when applicable, encoding, and padding.
  • Mode and block boundaries: Encryption mode, padding, and block boundaries affect what is compared across multi-block ciphertexts.
Slide 5 of 7 · Open in PDF
Easy explanation

XOR matching ciphertext positions, then count every 1 in the result. A hexadecimal digit represents four bits; simply counting different hex characters is not the same as counting different bits.

Example: For hex digits 7 and 0, XOR = 7 = 0111 binary, so three bits differ.

Key terms to remember
  • XOR comparison: XOR corresponding output bits; the 1 bits in the result mark positions where the outputs differ.
  • Hamming distance: The number of bit positions at which two equal-length bit strings differ.
Slide 6 of 7 · Open in PDF
Easy explanation

Correction: the printed ciphertexts differ in 30 of 128 bits, not 31. The whole-output rate is 30/128 × 100 = 23.4375% (about 23.44%). The unchanged second block affects that denominator.

Example: The first 64-bit block has 30 changed bits: 30/64 × 100 = 46.875%. Neither result proves security.

Key terms to remember
  • Avalanche percentage formula: The formula uses changed bits divided by total bits, multiplied by 100.
  • Ideal 50% interpretation: The slide says the ideal avalanche effect should be at least 50% or above.
  • Many-trial evaluation: Use multiple independent controlled input changes and inspect the distribution of changed output bits.
  • Avalanche is not proof: Avalanche behavior is one useful property but does not by itself prove cryptographic security.
Slide 7 of 7 · Open in PDF
Easy explanation

The assignment asks you to compare first-round behavior of original and enhanced Blowfish and to learn about statistical randomness tests. Make the variant and all settings explicit, use repeated trials, and do not treat a test pass as proof of security.

Example: Flip one input bit per trial, compare equal-length first-round states, and report the changed-bit distribution.

Key terms to remember
  • Statistical randomness testing: Testing output statistics can provide evidence about patterns, but passing tests alone does not establish security.
